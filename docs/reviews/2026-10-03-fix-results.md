# MacBootSwitcher 批量问题根因与修复记录

日期：2026-10-03。对象：原对抗性审查 R1–R11，加上 89 补充的“整个过程都慢、看不到当前步骤、缺少可理解日志”。状态：源码修复与非写入验证完成，真实授权及启动效果待独立窗口验收。

## 结论与根因

慢与缺少反馈有三个已证实的原因：重复读取磁盘；进程超时/取消不能及时收尾，输出管道可能阻塞；界面把授权、核验、系统设置放在同一等待状态。授权和 BootabilityService 自身是否还有额外瓶颈，当前没有端到端实测，不能把整段慢完全归因于其中一个阶段，也不能宣称已解决历史错误 101。

| 用户问题 | 原实现的根因及证据 | 本批修复 |
| --- | --- | --- |
| 扫描和提交前都慢 | 扫描按成员逐个 info 后，又重复读 System；执行 resolve 后再整机 scan。两个 System/Data 卷组共 22 次命令，16 次完全同参数重复 | 公开 `listVolumeGroups -plist` 直接读取成员关系；初次扫描每成员一次；授权后只核对所选目标及当前系统，不跨授权复用路径 |
| 等待像卡住，超时无效 | 旧执行器等退出后才读输出；取消任务不打断阻塞等待；仅 TERM 直接进程；重启另有阻塞执行器 | 集中使用参数数组执行器、持续排空输出、独立进程组、TERM/KILL 宽限、保留退出原因；重启复用同一层 |
| 看不出正在做什么 | 一个笼统“设置中”覆盖管理员弹窗、重新扫描和真正 bless；没有事件通道 | root 侧通过本次 socket 发送真实核验/设置事件，界面分阶段显示；扫描显示子步骤和候选计数 |
| 没有能理解的诊断 | 旧错误截断原文，既可能泄露账号/路径，又不能可靠区分取消和写入中断 | 固定允许名单文案、工具状态与阶段耗时；可展开事件记录；只把可信授权取消视为设置前取消 |

关键联系：提速不能删除授权后的身份守卫。旧实现既重复扫描，又把旧路径留到管理员等待之后。本批移除无用复查，把必须的新鲜核验放到实际 root 执行侧，同时解决性能与目标准确性问题。

## 只读测量

本机当时存在 4 个 System/Data 成员、2 个 System 卷组。没有真实 bless、授权、挂载、解锁或重启。

| 路径 | 命令数 | 单次诊断耗时 |
| --- | ---: | ---: |
| 旧初始扫描 | 8 | 1.588 秒 |
| 旧 resolve | 6 | 1.246 秒 |
| 旧写前整机扫描 | 8 | 1.573 秒 |
| 旧合计 | 22 | 4.407 秒 |
| 新初始扫描（真实 Scanner） | 6 | 0.998 秒 |
| 新授权后目标核验（只读调用） | 5 | 0.732 秒 |
| 新合计 | 11 | 1.730 秒 |

命令次数减少 50%。两组是不同探针、不同运行时的单次样本：旧为 Python subprocess 按旧调用链执行，新为 Swift Scanner/执行器并包含解析与可选版本读取；未控制缓存、负载和磁盘变化。耗时下降不能解读为完整切换必然快相同比例，不包含管理员等待、root 复制/签名、owner/系统服务或重启。后续实机窗口使用新增阶段耗时定位剩余等待，无需再盲猜阶段。

脱敏测量记录：`/private/tmp/MacBootSwitcher-review-scan-timing.json` 与 `/private/tmp/MacBootSwitcher-review-newscan-timing.json`。临时目录可能被系统清理；本报告保存统计结果，没有复制真实 UUID、账号或挂载路径。

## 按次授权实现与安全边界

GUI 创建 0700 随机目录和 0600 Unix socket，记录正在运行代码的 cdhash。提权脚本只携带应用路径、代码身份和本次 socket 地址，不包含目标、owner、密码或可自由选择的工具参数。管理员授权后，root 复制完整 App 到自己的私有临时目录，拒绝执行入口路径中的符号链接，移除其他用户写权限，严格验证代码签名与冻结 cdhash，再运行同一固定内部入口。副本用后清理，不安装 helper 或后台服务。

GUI 验证连接方 UID 为 root；runner 验证 GUI UID、目录及 socket 所有者与类型，限制请求结构/长度。root 固定 inode 锁贯穿执行；UI 失联不会使仍在执行的旧动作提前解锁。凭据通过 socket、随后 stdin 传递，不进入 argv、环境、普通临时文件或诊断。引用尽早清空，但 Swift 字符串与 Data 副本的物理清除无法保证。

非特权原型确认：只复制 Mach-O 无法满足完整 App 的签名上下文；完整 App 副本能通过正确 cdhash 校验，错误 cdhash 拒绝。此证据支持设计与打包，不代表管理员授权/复制/执行全链路已实测。当前使用本机 ad-hoc 签名，不等于发布签名、notarization 或跨机器安装已验收。

正常退出保护只协调应用层，不能拦截强杀、崩溃或断电。进程组只控制本次可控工具，不推断系统服务已停止，也不撤销已发生写入。工具失败不能排除部分设置；未知结果不自动重试、不重启、不修改持久默认盘补救。

## 进展与日志的用户表现

- 扫描：读取系统卷组 → 确认当前运行系统 → 核对候选（已完成/总数），显示实际等待秒数。
- 切换：检查所选目标 → 等待管理员授权 → 授权后重新核对目标 → 设置下一次启动 → 请求正常重启。待进行、当前运行、完成、取消、失败、无法确认分别显示。
- “查看操作记录”按时间显示固定阶段，例如“授权后重新核对目标…”及“设置下一次启动：结果无法确认（N 秒）”。不展示原始系统日志或编造百分比；授权期间提醒查看系统弹窗。
- 完成与失败页面保留记录；管理员取消返回列表也保留取消记录。工具成功仅说明工具报告成功，重启请求提交不说明机器已经进入目标系统。

## 最终验证与交付

最终源码测试命令见 `docs/validation.md`：**5 个套件，34 项通过，0 失败；测试 0.415 秒，编译 5.30 秒。**其中“100 个并行短进程”是 1 项测试，内部运行 100 次，不把它计成 100 项。

发现并修正过一项间歇性回归：过早关闭正在注销的 Dispatch fd，可能在其他命令复用 fd 时产生 spawn 失败或输出丢失。改为 cancellation handler 关闭，并加入并发复用回归测试。记录最终通过结果，不把修复前失败隐藏成始终通过。

最终 Release 增量构建 **5.01 秒通过**；`codesign --verify --deep --strict --verbose=2` 报告 valid on disk / satisfies Designated Requirement；Info.plist lint 和 3 个 shell 脚本语法检查通过。新版完整 App 的非特权复制再次验证：正确 cdhash 退出 0，错误 cdhash 退出 3。没有执行副本中的真实内部写入入口。

只读原生 UI 检查：本机启动扫描正确识别当前系统和一个可选目标；列表可选择并显示短标识；打开确认页核对相同短标识、覆盖原一次性选择、不查询恢复、可启动性与实机验收提示后取消。没有继续认证、输入凭据或执行切换。未做真实执行中窗口关闭、系统管理员弹窗、完整 socket/root 连接、设置进展或 TCC/重启的 UI 验收；进展行为目前由流程测试与静态视图核对支持。
