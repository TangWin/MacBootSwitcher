# 最小版架构设计

状态：实现及非写入修复验证已完成，真实授权、写入与启动效果待验收。更新日期：2026-10-03。

## 1. 产品目标

应用在本机当前 Macintosh HD 系统使用，用户打开窗口后选择另一套 macOS，按需认证，临时设置下一次启动并请求正常重启。默认启动盘始终不变。

支持已连接的内置、外置 macOS。首个实机验收目标为前序调查中的 Remote Work；程序不得硬编码这两个名称或设备编号。

### 最小版范围

- 启动自动扫描、手动刷新、目标选择、确认、认证、一次性设置、正常重启请求。
- 未挂载、锁定或信息不足的系统候选显示状态并禁用操作，由用户通过系统工具准备后刷新。
- 无菜单栏、开机自启、后台常驻、独立“仅设置”按钮、撤销或一次性启动目标查询。
- 不支持 Linux、安装器和恢复系统，不自动修复、挂载、解锁或准备启动卷。
- 不修改默认盘、安全策略或 SIP，不采用私有接口或未公开启动变量。

### 与旧版方案的变化

独立读取一次性目标、真正撤销已从需求删除，不再作为开发门槛。默认不变、一次性设置真实有效及安全认证仍须验证。`FEASIBILITY.md` 保留原始调查证据，不承担当前产品规格。

## 2. 模块与职责

```text
SwiftUI 主窗口（App）
          │
          ▼
切换协调器（Workflow）
    ├── 系统扫描与目标检查（Discovery）
    ├── 一次性启动操作与受限认证（Boot）
    └── 正常重启请求（Restart）
```

### App：窗口与应用入口

采用可调整大小的单窗口，展示当前系统、候选列表、名称、可读取的版本、内置或外置属性和就绪状态。主窗口提供“刷新”和“继续…”；后者打开合并的目标确认与拥有者认证页，最终动作明确为“认证并重启”。“打开磁盘工具”仅打开系统应用，不代替用户挂载或解锁。缺失的版本和存储类型显示未知，未就绪原因及处理指引直接展示。

确认页预填当前登录账户但不声称已确认拥有者资格，使用明确字段标签并预告稍后的系统管理员授权。取消按钮、Esc、系统关闭弹窗或关闭窗口均回到可选择状态并清空密码引用；提交后的弹窗关闭不得中止已开始的设置。选择支持键盘操作，刷新使用 Cmd-R，长内容可滚动，诊断记录默认折叠。

当前系统不能作为切换目标。没有就绪目标时禁用切换。选择必须由用户明确完成，不自动选中后执行。界面不展示无法独立验证的“下一次启动目标”；默认盘读取仅作为验证证据使用，不伪装成可靠的双状态查询。

确认文案至少表达：

> 此操作只指定下一次启动目标，不修改默认启动盘。设置成功后将请求重启。若随后取消重启，临时选择可能仍然有效；本版本不提供撤销功能。

并说明：如果此前已通过其他工具指定下一次目标，本操作将尝试覆盖该选择；应用不查询或恢复原临时目标。

### Discovery：发现与身份

- 通过公开的 `diskutil apfs listVolumeGroups -plist` 枚举 APFS 卷组；每个 System/Data 成员本轮只读一次 info，合并关联卷。根身份缺失或不唯一时扫描失败，不开放切换。
- 不把 Preboot、Recovery、Data 和当前根快照分别列成系统。
- 使用稳定的卷组身份；系统名称、路径和设备编号仅为显示或实时执行信息。
- 输入为当前系统提供的只读磁盘信息，输出为候选集合、当前系统身份和扫描错误。
- 每个候选最少包含稳定身份、名称、可选版本、内外置属性、是否当前系统、就绪状态及原因。未知状态必须显式保留，不编造缺失信息。
- 在执行设置前重新解析稳定身份，目标不一致、断开或未就绪就中止。
- 未挂载或锁定卷可以按可获得信息显示候选，但不能保证所有候选都能确认完整系统名称及版本。

### Workflow：协调与互斥

负责扫描、选择、确认、认证、重新核对目标、设置、解释结果及请求重启的顺序。一个应用实例同一时刻只允许一个操作；实际 root 执行侧持有 `/private/var/run/MacBootSwitcher.operation.lock` 的固定 inode 与 `flock` 直到工具结束，拒绝其他执行者，不依赖 UI 存续。

执行中禁用改选、刷新和重复点击。确认或认证等待后必须再次核对目标，不能直接使用旧扫描的路径。界面正常关闭应在写入期间提示等待，不能假设关闭应用可以撤销操作。

扫描展示读取卷组、识别当前系统、逐项核对候选的进展；执行展示检查、管理员授权、授权后核验、设置及正常重启请求。执行和结果页固定显示本次目标的名称与短标识，不因返回列表或清空选择而丢失本次目标上下文。步骤由适配层实际事件驱动，耗时使用单调时钟，事件日志仅包含固定阶段及分类结果。等待授权期间不跨授权缓存挂载路径、不预先重扫全机；受限执行侧仅核验所选目标。

结果类别与操作阶段分开保存：扫描失败、设置失败、设置未知、重启请求已提交、重启失败、重启未知分别呈现；重启失败或未知不使用成功配色。工具报告成功、写入阶段失败或结果未知时留下本次会话提醒。返回、刷新、扫描失败、取消新确认或管理员授权以及新的写入前拒绝均不得清掉已有提醒；仅新的写入反馈更新该提醒。提醒不持久化、不表示查询到了实际一次性目标，也不能证明它仍有效或已经失效。

### Boot：一次性设置与认证

对协调层只暴露针对稳定目标的一次性设置操作及明确的结果分类，不提供设置默认盘或任意命令入口。

- 使用本机文档确认适用于 Apple Silicon 的系统工具；每次设置必须携带一次性语义。
- 明确区分管理员提权与 local owner 认证，不假设二者是一回事。
- 实现前验证凭据传递机制。密码不得出现在命令行参数、临时文件、日志和持久化配置中。
- 优先按次执行且不常驻的最小权限方案；若必须安装 helper，先提交设计、签名与安装影响，由用户决定。
- 特权侧自己校验目标及参数，不能只信任界面验证。超时、异常退出和部分执行不得当作可安全重试。
- 操作结果至少区分：设置前取消、工具报告成功、工具报告失败、结果无法确认。错误码和输出须脱敏后解释，不编造系统成功语义。

不得以 `bless --getBoot` 的单项输出作为一次性目标读回。工具报告成功只能触发正常重启请求，不能证明实际启动成功。

### Restart：正常重启

只接受重启请求，不接受启动盘设置或任意脚本。使用可让应用保存文档、可被用户取消的系统机制；不强制结束应用，不调用强制重启兜底。

请求发出不等于机器已经重启。应用仍运行时可显示“重启请求已提交；若未完成，临时选择可能仍有效”，不把暂未关机误判为重启已取消。

## 3. 流程与失败行为

```text
扫描中 → 可选择 → 合并确认与拥有者认证 → 系统管理员授权 → 再次核对目标 → 设置中
                                                   ├── 工具成功 → 请求正常重启
                                                   ├── 工具失败 → 显示错误，不重启
                                                   └── 结果未知 → 显示无法确认，不重试
```

| 情况 | 必须行为 |
| --- | --- |
| 扫描失败或无可用目标 | 显示原因，允许刷新，禁用切换 |
| 设置前取消确认或认证 | 不执行设置，返回可选择状态 |
| 目标断开、身份变化或未就绪 | 中止并提示刷新 |
| 设置命令报错 | 不请求重启；若不能排除部分写入，明确状态可能不确定 |
| 设置进程超时、中断或输出无法解释 | 显示“设置结果无法确认”，不自动重试或重启 |
| 设置成功，重启失败、被取消或仍未完成 | 提示临时选择可能仍有效；不宣称撤销 |
| 应用退出或崩溃后重开 | 重新扫描，不凭历史记录推断临时状态 |
| 设置后外置目标被拔掉 | 不保证固件自动回退，不修改默认盘补救 |

不引入数据库、跨系统同步或状态恢复任务。最小诊断信息只包含脱敏的操作阶段、错误类别和必要退出结果。

## 4. 技术验证与交付界限

以下区分代码实现、非特权验证与实机效果，不将三者混为“已验收”：

1. **构建与运行环境**：
   - 确认在纯 macOS Command Line Tools 环境（无完整 Xcode.app）下，通过 SPM（`swift build` / `swift test`）构建原生可执行文件。
   - 操作与结果状态由 `SwitchWorkflow`（`ObservableObject` / `@Published`）集中管理；视图仅用 `@FocusState` 管理候选列表和密码框焦点，不以视图本地状态驱动启动操作。
   - `scripts/run-tests.sh` 显式加载 CLT 的 `TestingMacros` 插件；配置不在 `Package.swift` 的 swiftSettings 中。当前 5 套件、38 项真实解析/无害进程/模拟执行边界测试通过。

2. **接口与凭据安全传递**：
   - Apple Silicon 一次性设置接口确认为：`/usr/sbin/bless --mount <dir> --setBoot --nextonly --user <owner> --stdinpass`。
   - GUI 冻结卷组 UUID 与 System UUID，按次创建 0700 目录及 0600 Unix socket。提权脚本仅携带应用固定入口、当前运行代码 cdhash 与随机 socket 地址，不携带目标、owner 或密码。
   - 管理员授权后，root 创建私有临时目录，复制完整 App；拒绝执行入口路径中的符号链接，移除 group/other 写权限，并严格验证签名与冻结的 cdhash 后执行本次副本。无需安装或常驻 helper。完整 App 的正确/错误 cdhash 校验仅做过非特权原型实验，实际 root 提权全链路尚未验收。
   - GUI 核验连接方 UID 为 0；runner 核验 GUI UID 与目录/socket 所有者。仅接受固定 BootRequest 结构与有限长度输入，密码由 socket 传入再通过 stdin 送给 bless，不进入参数、环境、普通临时文件或诊断；清空引用不等于保证内存擦除。
   - runner 在授权后按稳定身份重新读取卷组、根系统、所选 System/Data 与即时挂载对象，5 次只读命令全部通过后才执行唯一带 `--nextonly` 的命令。最终核验与系统工具执行之间不是原子操作，扫描与核验都不保证可启动。
   - 执行器用参数数组及固定绝对路径创建独立进程组，启动后持续排空两路输出；超时/取消发 TERM、宽限后 KILL，保留工具退出与信号退出区别。Dispatch 源注销后才关闭 fd，避免并发复用误伤。重启复用该层。
   - 上述进程组控制不能保证终止由系统服务继续处理的工作，也不能撤销已发生的写入；超时、失联、信号退出归结果未知，不重试、不重启。

3. **默认目标不变的核对依据**：
   - `/usr/sbin/bless --getBoot --plist` 只保留其报告范围的证据；不单独解释为一次性目标查询或持久默认未变的完整证明，不复用历史设备号。
   - 本批开发没有调用真实启动写入或重启。测试中的 Scanner 配模拟 diskutil 输出，执行器测试使用真实非特权无害工具；真实写入边界使用模拟命令。不能以代码没有默认盘入口代替实际一次性效果与默认不变的验收。

4. **实机验收界限**：
   - 阶段 D 涉及真实启动写入与重启，须由 89 安排操作窗口后手动配合进行两次启动验证；普通开发阶段不触发实机写入。
